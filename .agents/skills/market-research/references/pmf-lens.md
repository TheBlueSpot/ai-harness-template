# PMF Lens

Use this lens when comparing products or rewriting roadmap bets.

## Highest-Level Summary

Answer these first:

1. Who is product for right now?
2. What first-5-minute problem does it solve better?
3. What recurring loop makes user come back?
4. What trust or portability friction does it remove?
5. Which 3-5 bets matter for our roadmap?

## Evidence Checklist

Prefer primary sources in this order:

1. official site or docs
2. repo README and roadmap files
3. recent releases or changelog
4. open issues with repeated pain or strong reactions
5. pricing or packaging pages

## GitHub Repo Checklist

Read enough to answer:

- what install path is promoted
- what providers or runtimes are supported
- whether product is desktop, web, CLI, or remote-first
- whether repo exposes roadmap, TODO, releases, or issue demand
- what workflow features appear core versus incidental

Good signals:

- simple install path
- recent stable releases
- explicit remote or packaging story
- issue clusters around missing but desired workflows
- docs depth around onboarding, trust, and observability

## Product Site Checklist

Read enough to answer:

- headline promise
- target user
- onboarding path
- proof of trust or safety
- pricing or portability story
- change velocity

## Roadmap Rewrite Rules

- Translate competitor features into user problems first
- Add only bets that strengthen this repo's product focus
- Prefer smaller roadmap items that can ship end-to-end
- Push broad surface-area expansion below activation and daily-loop work
- Keep non-goals explicit if research suggests distracting expansion

## Good Recommendation Shape

For each proposed roadmap change, capture:

- bet
- why it matters
- expected PMF impact
- likely urgency: now, later, or avoid
