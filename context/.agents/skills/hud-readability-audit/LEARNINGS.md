# Durable Learnings

- HUD readability is a catalog-level skill gap when notes stay flat. Blocker-first outputs make different game audits comparable instead of opinion-heavy.
- Busy-frame evidence matters because many arcade HUD failures only appear during particles, reward bursts, subtitles, or stacked overlays, not in calm screenshots.
- Readability fixes are often mechanic-preserving. Stronger contrast, redundant cue channels, and lower edge scan load usually improve sticky play without redesigning the core loop.
- HUD audit should reject calm-screen false passes. For this catalog, one missing busy-frame sample is more dangerous than one pretty screenshot because peak clutter is where sticky arcade readability usually breaks.
- A critical-read matrix matters for this catalog because repeated HUD failures usually come from the same few signal breakdowns; logging them per state and cue makes cross-game comparison faster than prose-only notes.
- Animated UI noise matters because a calm-screen HUD can still fail when blinking, scrolling, or auto-updating widgets steal attention from an urgent read.
- Animated UI noise counts as gameplay clutter in this catalog because moving overlays can steal attention from the current read even when the static HUD layout looks clean.
- Must-react cue review is stronger when it logs the needed response and future path explicitly, because a warning that only says danger exists can still fail sticky arcade play at the actual choice moment.
- Cue-competition logging matters for this catalog because sticky arcade HUD failures often come from `which urgent thing wins` rather than one broken widget; overlapping warnings need one dominant read before more polish discussion matters.
- telegraph-test: blocker-first HUD reporting matters for this catalog because sticky arcade games depend on fast peripheral reads under pressure; this run logged 1 blocker(s) and 0 major finding(s), including animated UI pressure where moving or auto-updating elements competed with urgent reads, instead of screenshot-only taste notes.
- priority-stack-test: blocker-first HUD reporting matters for this catalog because sticky arcade games depend on fast peripheral reads under pressure; this run logged 3 blocker(s), 1 major finding(s), and 1 cue-competition risk moment(s), so overlapping warnings get judged as gameplay clarity failures instead of screenshot-only taste notes.
- HUD review should log temporary prompt recovery for this catalog because a warning can be visually readable and still fail if it disappears before the player can recheck it, while non-critical popups can become gameplay blockers when they cannot be suppressed.
- temp-ephemeral-test: blocker-first HUD reporting matters for this catalog because sticky arcade games depend on fast peripheral reads under pressure; this run logged 1 blocker(s), 2 major finding(s), and 1 cue-competition risk moment(s), so overlapping warnings get judged as gameplay clarity failures instead of screenshot-only taste notes.
- Shared playtest starters should flow into HUD review with their guardrails, incidents, and probe load intact, because one short browser-play session can prove a local readability break without proving the whole HUD is solved or broken.
- HUD review should log cue-channel fallback for this catalog because a warning that reads only by color or only by sound can pass one fast session and still fail real sticky arcade play under mute, color ambiguity, or screen-noise pressure.
- hud-skill-smoke: blocker-first HUD reporting matters for this catalog because sticky arcade games depend on fast peripheral reads under pressure; this run logged 1 blocker(s), 3 major finding(s), 1 cue-competition risk moment(s), and 0 channel-fragile cue(s), so overlapping warnings and one-channel reads get judged as gameplay clarity failures instead of screenshot-only taste notes.
