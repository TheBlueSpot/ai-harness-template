Browser-playable action-platformer slice for the `context` game collection.

- Core hook: a torchlit keep, roaming skeletons, and a spectral mirror escape route.
- Session flow: start from the title card, gather three sigils through one connected castle, then leave through the awakened mirror.
- Gameplay texture: the entry keeps its moody shadowed look while still reserving enough lift for active platforms, enemies, and the exit route to read during play.

## Sweep learnings

- Dark-mask platform rooms keep their mood better when footholds, enemy silhouettes, and the sleeping exit gain a selective readability lift instead of raising the whole room brightness.
- In dark-goal rooms, objective clarity holds up better when the dormant destination and the active escape both keep an in-world anchor, because the player should not need to translate a HUD note into a guessed location.
- Exposed footholds read better when the post-light pass lifts the full platform body and skeleton rim a little, because a bright top lip alone still leaves jump landings and enemy positions too easy to lose in the dark.
- In torch-mask platformers, fixing platforms and enemies first still leaves one live blind spot if the avatar stays darker than both; the player silhouette and attack path need the same selective floor in the deepest pockets.
- In side-scroll spaces with a separate objective HUD card, the offscreen beacon still has to carry direction plus target context on its own, because a tiny generic `SIGIL` or `EXIT` chip is too much translation work during active movement.
- In dark objective rooms, collectible goals need the same post-light readability floor as footholds and enemies, because a strong HUD label still fails if the exact pickup disappears once the player reaches its platform.
- In layered platform rooms, an offscreen objective cue should name vertical travel as well as left-right chase, because a target one floor above otherwise reads like bad horizontal guidance instead of a jump-route instruction.
- In dark platform rooms, a cue can still fail readability by hiding the route it explains, so live objective plaques should stay short and let the HUD carry the extra sentence-level detail.
- In single-screen castle layouts, the remaining cue tax can come from the objective beam itself, so target anchors should bias toward side chips and connector lines instead of tall overlays through the live jump lane.
- In single-screen platform rooms, transient HUD copy should share the existing objective dock instead of floating through the center top of the playfield, because repeated goal reminders compete with the same upper footholds and route reads the player is trying to parse.
- In compact route-heavy platformers, the objective HUD should spend its one detail line on immediate route geometry rather than generic progress prose, because `1 tier up, 4 spans right` answers the live movement question faster than `3 remain in the keep`.
- In side-facing action rooms, a whip or melee path has to mirror its forward arc on both facings, because players read attack trust from the silhouette of the strike before they judge its exact hitbox.
- In vertical platform routes, a generic `CLIMB UP` note still reads like bad jump tuning if the player cannot see the first reachable step, so the route helper should point at the next ledge or drop instead of only naming the target tier.
- In small platform rooms, a route cue can still read false when jump timing is brittle, so adding coyote time plus a short landing buffer can solve a `where do I go?` complaint without changing the stage at all.
- In dark route-heavy platform rooms, a step helper should highlight the exact landing strip as well as the destination tier, because a correct arrow still leaves doubt if the player must guess which slice of platform is actually safe to aim for.
- In compact platform rooms, the last route-read miss can be edge choice instead of platform choice, so climb/drop helpers should bias their strip toward the actual entry or exit lip rather than centering it across the whole ledge.
- In vertical platform routes, an upward helper should reject the support band the player already stands on, because re-highlighting the current floor still reads like bad jump guidance even when the strip itself is accurate.
- In edge-anchored route beacons, the next move and the target should live in separate high-contrast bands, because players glance at edge cues mid-jump and small stacked lines cost too much read time.
- In offscreen platform routes, the edge beacon should inherit the same left/right lip choice as the landing-strip helper, because the exact touchpoint still matters while the destination ledge is outside the camera.
- In offscreen platform routes, the last route-read miss can be text-only edge naming, so the beacon should echo the intended lip as a tiny landing-strip shape instead of making the player translate `left/right lip` during movement.
- In offscreen route beacons, the last surviving readability miss can be where the lip side sits, not whether the lip shape exists, so `left/right lip` should become its own strong cue instead of staying buried in a softer detail sentence.
- In offscreen route beacons, the fastest lip-side cue is side placement itself, so `LEFT EDGE` or `RIGHT EDGE` should sit on the same side of the preview slab the player needs to approach instead of hiding as centered copy.
- In compact platform rooms, offscreen route fixes can still land too late on their own; the first reachable step should repeat the same lip-side instruction so the player does not lose the side choice when the target ledge comes back on screen.
- In compact platform rooms, a correct route-step plaque can still read badly if it sits on top of the landing strip, so the label should ride beside the step with a short connector and leave the jump lane itself unobscured.
- In single-screen route-heavy platformers, a landing strip that spans the whole tile can accidentally erase the left/right choice it is supposed to teach; narrowing the strip enough to bias one entry edge lets a lip marker carry the route in shape instead of extra prose.
- In compact vertical routes, repeated cue refinements can stop helping once the first reachable foothold stays offscreen too long; at that point the smaller truthful fix is earlier camera reveal rather than another label pass.
- In layered route stacks, closing the main offscreen objective panel is not enough on its own; the smaller `NEXT LEDGE` or `SAFE DROP` beacon has to repeat the same side-pinned lip badge or the route-trust residue just moves to the first hidden foothold.
- In compact HUD cards, transient helper text still fails if its baseline lands on the panel border, so live-note docks need explicit bottom breathing room instead of relying on tight one-line fits.
- In compact action-platform rooms, once route labels are already truthful, the next false-read can come from the move itself; a small jump-height lift plus slightly longer coyote and buffer grace can clear `this ledge is too high` complaints faster than adding yet another path cue.
- In dark platform fights, a thin enemy swipe line is easy to lose against nearby footholds and plaque copy, so attack timing should also claim a small floor lane near the threat instead of living only in the enemy silhouette.
- In dark platform fights with vertical movement pressure, a floor-lane attack tell still lands too low once the player is reading an upper lip or landing strip, so the same swing warning should repeat at eye level over the attacker.
- In compact action-platform fights, a connector cue can still turn into clutter if it fills the whole climb lane; leaning that link forward toward the strike edge keeps the telegraph unified while freeing more of the nearby jump-lip read.
- In compact action-platform fights, once the strike lane itself already reads clearly, the next false-read can move from telegraph shape into telegraph duration, so the cheaper truthful fix is a slightly longer windup before changing the route cues again.
- In climb-heavy combat reads, once the enemy telegraph itself is mostly truthful, the next readability miss can be simple side resolution under pressure; duplicating `left/right` danger at the player focal point is cheaper and clearer than adding more route text.
- In climb-heavy combat reads, a focal cue can still miss if direction and verb share one thin line, so splitting `LEFT/RIGHT` into its own side badge and letting `SWING` carry the action word reads faster than asking the player to parse a compact sentence while landing.
- In climb-heavy combat reads, side-only warnings still leave one timing translation on the table, so the same focal cue should show the windup filling toward contact instead of asking the player to infer strike timing from the enemy sprite while also reading the next foothold.
- In compact combat-platform climbs, once side and strike-lane cues already read, the last false-read can be that the attack becomes live before the player can act on the cue; extend the readable windup before adding more labels or retuning route helpers.
- In compact combat-platform climbs, a truthful swing cue can still fail if it sits in the same upper lane as the next foothold, so the better last-step readability fix is shoulder-docking the warning to the danger side instead of stacking more copy over Belmont's jump path.
- In compact combat-platform climbs, once side-docked danger already preserves the jump lane, the next cheap truth lift is an explicit `WINDUP -> HIT` countdown strip with a live contact pip, because a tiny phase word still costs too much parsing time at the exact moment the player is choosing jump or dodge.
- In compact combat-platform climbs, once the swing rail itself is truthful, the next readability miss can be raw label scale; larger phase cells beat another sentence when the player only has one shoulder-glance before choosing jump or dodge.
- In compact combat-platform climbs, once the shoulder cue already names side plus timing truthfully, the next readability win is reducing live choice count: one large active phase label beats three tiny simultaneous phase options when the player is mid-jump.
- In compact combat-platform climbs, the timing rail should visually break out the `ready` and `live` windows, because a lone end pip still leaves too much timing translation at the exact jump moment.
- In compact combat-platform climbs, once danger side and strike timing already read clearly, the last cheap readability miss can be response translation itself; naming the safe escape side (`GO LEFT` or `GO RIGHT`) is truer than adding more threat wording.
- In compact combat-platform climbs, once the shoulder cue already gives the safe move, the `LIVE` contact window still needs to read like a hard hazard block rather than a thin rail tint, because jump pressure leaves room for one shape-first danger glance, not another timing parse.
- In compact combat-platform climbs, one cue can still stay too dense if it shows both the danger-side direction and the safe-move direction as competing words, because mid-jump the player gets two opposite text reads at once.
- Once danger side is already obvious from placement and connector geometry, the shoulder badge should switch to `THREAT` or `DANGER` and leave the only directional text on the safe-move command itself.
- In compact combat-platform climbs, once a large safe-side arrow already carries escape direction, the cheapest last cue-read win is cutting `GO LEFT` and `GO RIGHT` entirely so the shoulder card spends its word budget on one short action verb instead of left/right text parsing.
- In compact combat-platform climbs, once the shoulder cue already reads clearly, the next false-read can be stacked recovery pressure rather than label density; a nearby attacker should briefly own the lane so the player can act on one dodge read before another same-band swipe starts.
- In compact combat-platform climbs, phase truth beats raw proximity once more than one attacker is winding up; a focal danger card should always prefer a live strike over a nearer pre-swipe windup or it teaches the wrong dodge on the exact contact beat.
- In compact castle climbs, once shared same-band spacing is truthful, the remaining false-read can still be one authored ascent that is covered from both sides; move one guard off that climb before reopening global combat-read logic.
- In compact castle climbs, if one authored two-sided squeeze still survives the shared spacing rules, the smallest coherent readability fix is another spawn-tile nudge on the far-side guard before touching telegraphs or global pursuit again.
- In compact combat-platform climbs, holding the second attacker’s swipe timer is not enough on its own if that follower still chases into the same band at full speed; the cleaner readability fix is to let the recovering attacker own a short spacing buffer so the next dodge read does not collapse back into shoulder clutter.
- In compact combat-platform climbs, once a shoulder card already has one danger badge, one action verb, and a timed rail, any extra helper sentence or repeated verb phrase becomes pure scan tax; cut duplicate threat wording before adding another visual treatment.
